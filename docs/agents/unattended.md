# Unattended sessions

`STACK_MONITOR_UNATTENDED=1` means no one is in the chat; the monitor's `agents.env` sets it for headless runs. Every gate below that asks for a **decision** is replaced by the recommended answer, recorded where a reviewer can find it: the plan's Open questions or an issue comment. The PR body carries a decision only when someone has to act on it (§ PR body and closing comment). A gate that guards a **destructive or irreversible** action stays a stop: force pushes, `git worktree remove --force` or `git branch -D`, deleting a file the user may not have meant, staging a secret, overwriting a hand-edited PR body. A stop is an issue comment (`gh issue comment <n> --body-file <file>`) saying where and why, then end the turn. If `gh` can't reach the issue, or the run has no issue, the same text goes in a PR comment (`gh pr comment`, or the PR body if there is no PR yet), and the turn ends with it as the report.

An unattended run on an issue starts only if the issue carries the `ready-for-agent` label (`docs/agents/triage-labels.md`; the `triage` skill sets it after the grill). Check with `gh issue view <n> --json state,labels,assignees` before the assign step and before cutting a branch. Without it (including an issue that's closed, not evaluated, `needs-info`, `ready-for-human` or `wontfix`), post an issue comment naming the missing label, leave the assignee alone, and end the turn. A run with no issue is not subject to this.

Issues reach `ready-for-agent` through triage: the `triage` skill evaluates open issues that carry `needs-triage` or no category label, grills if needed, writes the brief, and labels them.

The end state of a run is a PR with its before/after output in the body and the review pass done, marked ready for review (`gh pr ready`). The PR body's `Closes #<n>` is what puts the issue In Review: check that `gh issue view <n> --json closedByPullRequestsReferences` lists the PR, and add the line to the body (`gh pr edit --body-file`) if not. Then the closing issue comment (§ PR body and closing comment). A run that stopped early leaves the PR a draft, and so does the table's **Open finding** row. The final review, approval and merge are a human's.

## PR body and closing comment

The PR body is `pull-request`'s § Body, whose summary ends with `Closes #<n>`. The one addition is a bug's before and after output (`fix-bug` § 6). A decision reaches the body only when the reviewer, or someone running the monitor, has to act on it (a config change that breaks an existing `stack-monitor.json`, a changed MCP tool an agent may already call, a changed style guide), as one line in Review notes, inside that section's limit. What the rows above send to the PR body is one line each: a bug's cause and fix in the summary, an ambiguous file's commit and the changed guides in Review notes. A skipped review finding goes in Review notes only when a reviewer must weigh it before approving.

The closing issue comment links the PR and carries the rest: the decisions taken, the review findings applied and skipped, and the disclosures (checks not run). A decision the plan's Open questions already records is a link to it, not a copy. When `gh` can't reach the issue, or on a run with no issue, it goes on the PR as a comment.
